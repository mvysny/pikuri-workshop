# Changelog

All notable changes to the workshop gems. pikuri's own changes are in
[its changelog](https://github.com/mvysny/pikuri/blob/master/CHANGELOG.md).

## [Unreleased]

- Every workshop gem now requires pikuri `~> 0.2.0` (was `~> 0.1`, which let pikuri 0.2's breaking changes in) and is built against pikuri 0.2.0 from rubygems; upgrade pikuri's gems alongside.
- `pikuri-vectordb` moved here from pikuri unchanged (pikuri `43ecf1e`): pikuri 0.2.0 no longer ships it, and its changes since pikuri 0.1.0, its last release there, are in pikuri's 0.2.0 changelog.
- Add `pikuri-rag`, moved here from pikuri unchanged (pikuri `43ecf1e`), which never released it: hybrid retrieval over a local corpus as `rag_search` (a vector leg and an FTS5 keyword leg fused by reciprocal rank, optionally reranked), `rag_search_keywords` (every document holding all the stemmed words, no cutoff) and pikuri-vectordb's `rag_read` / `rag_reindex` (`D_rag_gem`).
- `pikuri-corpus` moved to `pikuri-rag/bin/` and gained `--hybrid`, which swaps its `vectordb_*` tools for rag's over the same corpus and collection.
- Fix `Pikuri::Conversations::Conversation` showing two messages sent during a boot, or a message kept across a cancel and the next one, in reverse order: `TurnStarted` named the later message ahead of the earlier one's `UserTurn`, so such a turn is now bare, `user_message: nil`, and delivers them all, in order, as mid-loop `UserTurn`s.
- **Breaking:** `Pikuri::Conversations::Event::PendingChanged` carries `items:`, the waiting `Interloper::Item`s in delivery order (`:user` and `:system`), instead of `count:`; `count` still reads and pattern-matches as `items.size`, but build the event with `items:`, and a boot that takes its only waiting message for the first turn now reports `[]` rather than leaving the last count standing (pikuri `9b6a7e3`).
- **Breaking:** pikuri-os's file index moved to pikuri's new `pikuri-fileindex` gem (pikuri `51fec91`): `Pikuri::Os::{FileIndex, LocalSearch, Recoll, FileindexSearch, FileindexRead}` are gone for `Pikuri::Fileindex.pick`, `Fileindex::{LocalSearch, Recoll, Search, Read}`, and `Os::Extension` wires them over the whole disk (`Os::Extension::FILE_INDEX_ROOTS`), so `fileindex_search` now ranks hits, quotes 40-word localsearch snippets, gives each file's text size and the count of all matches, `fileindex_read` takes a `pattern`, and neither returns a file under a hidden folder.
- `Pikuri::Extractors::Documents` runs its converter container on podman when it is installed, else docker, as `Mem0Server` does (`runtime:` forces either).
- `Pikuri::Memory::Mem0Server` runs the stack on podman when it is installed, through a private `podman system service` it starts and stops itself, and falls back to docker (`runtime:` forces either).
- **Breaking:** `Pikuri::Memory::Mem0Server.new(llm_model:)` is now `extraction_model:`, a `Mem0Server::ExtractionModel` (`name:`, `params:`) whose `params` mem0 sends with every extraction call, so the chat model can extract with thinking off; `bin/pikuri-memory` defaults to exactly that (`extraction_model` / `extraction_params` override it).
- Fix `Pikuri::Memory::Mem0Server` breaking on any embedder but a 768-wide one and on a router with an API key: it now asks the embedder for its vector size (`embedding_dims:` still overrides; `DEFAULT_EMBEDDING_DIMS` is gone), refuses to boot over a stored collection of another size, and takes the router key as `api_key:`, which `bin/pikuri-memory` reads from `llm_api_key`.
- **Breaking:** `Pikuri::Stemmers::Voikko` owns its `::Voikko` handle and closes it from `#close`, which the `Fts5` it is handed calls when its corpus closes (pikuri's new stemmer `#close`); stop closing the handle yourself.
- Fix `git_repo_research`'s child running out of context ending the parent's whole turn; `Pikuri::Code::GitRepoResearcher` now answers it as a tool error telling the parent to give the agent a narrower task, as pikuri's `agent` tool does (pikuri `85f96cf`).
- **Breaking:** `Pikuri::Conversations.new(system_prompt:, configure:, on_turn_end:)` is now `Pikuri::Conversations#open(initializer:, saver:)`, given per conversation: move the prompt and the tools into an object including `Conversations::AgentInitializer` (`system_prompt(conversation)`, `configure(configurator, conversation)`), and the save into one including `Conversations::Saver` (`save(conversation, history)`).
- Hand `Pikuri::Conversations::Throttle` to `Pikuri::VectorDb::Embedder.new(around_request:)` and `Reranker::LlamaServer.new(around_request:)` too (pikuri `4106ddd`), so a RAG reindex queues with the chat on a small llama-server; a separate embedding server stays unlimited until you `Throttle.limit` it.

- New `pikuri-stemmers`: `Pikuri::Stemmers::Voikko`, the Finnish stemmer for pikuri-rag's `stemmer:`, moved unchanged from pikuri's `Rag::Stemmer::Voikko` (where it is gone); rename the constant where you build one (`D_voikko_stemmer`).
- **Breaking:** `Pikuri::Code::Extension` and `Pikuri::Os::Extension` take `plan_mode:`, a new `Pikuri::Code::PlanMode`, instead of pikuri's dropped `Workspace::ReadOnly`; hand `Workspace::Extension` the filesystem `plan_mode.guard(filesystem)`, and `Code::Extension::PLAN_MODE_READONLY_MESSAGE` is now `PlanMode::REFUSAL`.
- **Breaking:** `Pikuri::Code::GIT_REPO_RESEARCHER` is now `Pikuri::Code::GitRepoResearcher`, an extension adding the `git_repo_research` tool whose child agent works in a throwaway folder of its own, since pikuri dropped the sub-agent temp workspace; `Code::Extension` no longer registers `git_clone`, and `GitClone#with_workspace` is gone.
- Add `Pikuri::Code::TmpAlias`, which makes the file tools read `/tmp` as a scratch folder that `Bash::Sandbox::Bubblewrap` binds at `/tmp`, replacing pikuri's dropped `Filesystem` `temp:` and `alias_tmp_to_temp:`; mint the folder with `Paths.new_temp` and list it as `writable:`.
- `Bash::Sandbox::Bubblewrap#env` adds the host's git identity, which pikuri's dropped `Filesystem#env` supplied, and `Bash.withheld_env_names` no longer takes `filesystem:`.
- pikuri-code no longer depends on pikuri-subagents.
- Fix `Pikuri::Code::Extension`'s plan-mode bridge leaking: it now unsubscribes from the shared plan-mode flag on close, so a `/clear` no longer keeps the closed conversation in memory.
- Add `Pikuri::Code::WholeDisk`, moved from pikuri's `Workspace::Filesystem::AllowAll` (where it is gone) with the same arguments and credential denylist; rename the constant where you call it.
- Add `Pikuri::Code::ProjectRoot`, moved from pikuri's `Workspace::ProjectRoot` (where it is gone): the VCS-marker climb that picks a coding agent's project root. Rename the constant where you call it.
- `Pikuri::Lsp::Readiness#wait` yields each indexing task once when it starts and once when it ends, no longer every report, and `ServerProgress` is a plain domain event, since pikuri dropped `Agent::Event::Transient` (`pikuri:D_domain_events`).
- **Breaking:** `Pikuri::Mcp::Extension.new(registry:, synthesize_descriptions:, verify_mcp_servers:)` is now `Pikuri::Mcp::Extension.new(catalog:)`, one per agent: build the catalog once per process with `Pikuri::Mcp::Catalog.build(registry, transport:, cancellable:, around_request:)` and hand it to every agent (`D_mcp_catalog_and_connections`).
- **Breaking:** `Pikuri::Mcp::Servers` is gone, split into `Pikuri::Mcp::Catalog` (verified once, shared, holds no process) and `Pikuri::Mcp::Connections` (one agent's own servers, started on its first tool call); `Pikuri::Mcp::Servers::Connect` is now `Pikuri::Mcp::Connect`.
- An MCP server process now serves one agent only and starts on that agent's first call to its tools, so a browser logged in during one conversation is never logged in for another, and building an agent spawns nothing.
- **Breaking:** an extension instance added to a second agent now raises `ArgumentError` (pikuri's `Configurator#add_extension`), so a host that reused one `Tasks`, `Skill`, `Memory`, `Lsp` or `Mcp` extension across agents, quietly sharing its task list, skill gate, capture queue or servers, must build one per agent; every agent starts its own language servers (`D_lsp_per_agent`).
- A resumed conversation (`Agent.new(history:)`) gets back the tools of every MCP server it connected, without calling `mcp_connect` again.
- A spawned MCP server that lists different tools than the ones verified at boot is refused with `Pikuri::Mcp::ClientWrapper::SurfaceChanged`, including after a crash restart.
- The MCP verifier's and synthesizer's one-shot agents take the host's `around_request:`, so a request throttle covers them too.
- New `pikuri-conversations`: `Pikuri::Conversations::HistoryFile` stores a conversation in the format pikuri's dropped `History#save` / `.load` wrote, and `Pikuri::Conversations::Store` keeps one folder per conversation as pikuri-webui and Puri did (`D_history_file`).
- `Pikuri::Conversations::Store#history` answers nil for a conversation never saved, so a host passes it straight to `Conversations#open(history:)` without checking for `history.json` first.
- `Pikuri::Conversations::Conversation#close` closes a booting conversation no message waits on, answering `:closing`, so a host deleting it no longer needs `force: true`.
- `Pikuri::Conversations::Conversation#boot` is public, so a host whose listener reads the conversation back opens it with `boot: false` and boots it once it holds it.
- `Pikuri::Conversations::Conversation#close(force: true)` and `Conversations#shutdown` now run `on_turn_end` for the turn they cut short, so a quit keeps what was said; `shutdown(timeout:)` waits for those saves.
- `Pikuri::Conversations::Store#delete` is final: a later `save`, `stash` or `retitle` of that conversation writes nothing, so a host deleting a conversation whose turn is still unwinding needs no guard of its own.
- New `Pikuri::Conversations::Status#busy?`: a turn runs, or a boot has a message waiting — what a host shows as "working", including after a boot cancelled before its turn.
- `Pikuri::Conversations::Probe::Detector` never dials a `.invalid` host, so a host's specs on `Pikuri::Testing.fake_transport` no longer need `Throttle.limit('http://fake.invalid', nil)` or a stubbed `Detector`.
- `Pikuri::Conversations::Event::Closed` is now a conversation's last event and comes once, a racing `Titled` or another thread's event heard before it, and `Conversations#shutdown` and `Conversation#wait_closed` return only once it has reached the listener, so a host's teardown no longer races a late title write.
- `Pikuri::Conversations::Conversation#wait_settled(timeout)` returns once no boot, turn or title of the conversation is in flight and every event they emit has reached the listener, so a host's specs need not poll for thread names.
- **Breaking:** `Pikuri::Conversations::Conversation#inject_system` is gone: `submit(text, system: [skill])` puts reference blocks ahead of the message in one turn, whatever state the conversation is in, and `submit(system: [skill])` delivers them alone.
- A skill the human loads (`Skill::Extension#schedule_load_skill`, or `Skill::Renderer.format_skill(skill, by_user: true)`) tells the model "The user loaded this skill.", where the `skill` tool's own load says nothing of the kind.
- `Pikuri::Conversations::Conversation#clear` while booting starts that boot over from the empty history instead of answering `:busy`, so a `/clear` typed while the agent is still starting is no longer refused.
- `Pikuri::Conversations::Event::Cleared` reports every `Conversation#clear`, a clear with no agent to replace included, so a transcript starts over on it rather than on `Booting`, which a retry after `BootFailed` emits too.
- `Pikuri::Conversations` runs many conversations at once, each a `Conversation` with its own agent and turn threads: `submit` starts a turn or injects into the running one, and `cancel`, `switch_model`, `clear`, `close` and `shutdown` are safe from any thread.
- `Pikuri::Conversations::Throttle` bounds the LLM requests in flight per server, process-wide, sized by `Throttle.limit` or from llama.cpp's `/props` slot count, which a conversation probes once per server and model; it replaces the `ServerPermits` pikuri dropped.
- `Pikuri::Conversations::Probe` asks llama.cpp's `/props` for a model's context window, slot count and inputs, in place of the `ContextWindowDetector` pikuri dropped, and hands the agent what it learns; `Pikuri::Conversations::Event::ContextCap` announces the window to the conversation's listener, in place of pikuri's `Agent::Event::ContextCap`.
- `Pikuri::Conversations::Titler` names a conversation from its opening message, the prompt pikuri-webui and Puri used; a conversation opened `untitled: true` asks it once its first turn has ended and reports `Event::Titled`.
- `Pikuri::Conversations::RateLimitedListener` coalesces streamed deltas to an fps cap, in place of the `Listener::RateLimited` pikuri dropped: it flushes ahead of a turn's end, even a failed one's tail and a failed sub-agent's, and passes the conversation's own events (`Pikuri::Conversations::Event::ALL`) straight through, so it needs no lock.
- **Breaking:** `Pikuri::Code::Bash.run` and `Pikuri::Code::ExitPlanMode.run` take a required `cancellable:`, which the `bash` and `exit_plan_mode` tools pass from the turn, so a cancel reaches their confirmation while it still waits on the human.
- The workshop requires pikuri `4baa207`, where `Agent::ListenerList` is itself a listener, so a host hands several to `Conversations#open(listener:)` as one, and before it `863c1ad`, where `Confirmer#ask` takes the turn's `cancellable:`, and before it `0e5882f`, where an `Agent` never probes the server and announces no context window, and before it `3aed7e2`, where an `Agent` is one conversation, owns its `Interloper`, takes `around_request:` in place of `ServerPermits`, refuses a reused extension instance, and gives an extension one setup hook, so every workshop extension's `bind` moved into `configure`.
- **Breaking:** `Pikuri::Mcp::Connect.new` takes `configurator:` in place of `ctx:`, `Pikuri::Mcp::Connections#register_tools` takes the agent's `Pikuri::Agent::Configurator`, and `Pikuri::Memory::Extension#on_user_message` / `Pikuri::Code::Extension#on_user_message` take no `ctx`.
- **Breaking:** `Pikuri::Skill::Extension#on_conversation_reset`, `Pikuri::Skill::Activation#reset` and `Pikuri::Skill::Activation::Open` are gone: a new conversation is a new agent with a new extension, and every agent has an interloper to carry a promotion.
- **Breaking:** `Pikuri::Tasks::Extension#on_conversation_reset` and `Pikuri::Tasks::List#clear` are gone, since a new conversation's agent gets a new extension and an empty list.
- `bin/pikuri-code`'s `/clear` closes the agent and builds a new one, so MCP and language servers restart and nothing a conversation touched crosses into the next.
- `pikuri-memory`'s Qdrant image is `docker.io/qdrant/qdrant:v1.12.4`, fully qualified like pikuri-vectordb's, so podman finds it without a registry prompt.
- `pikuri-code`, `pikuri-os`, `pikuri-lsp`, `pikuri-mcp`, `pikuri-skills`, `pikuri-tasks`, `pikuri-memory` and `pikuri-extractors` moved here from pikuri; a host that wires one now takes it from this repo, beside pikuri's own gems (`D_separate_repo`).
- The workshop gems carry their own version (`Pikuri::Workshop::VERSION`) and pin pikuri's gems with `~>` instead of pikuri-core's exact version.
- `pikuri-extractors` tags its converter image with a digest of its build context instead of pikuri-core's version, so an unchanged image is never rebuilt.
- `bin/pikuri-code` asks "did you write the files under this directory?" only when the project ships a skill or a slash command, and its `--yolo` help and reduced-safety banner now point at a VM rather than a container.
- `bin/pikuri-os` and `bin/pikuri-computer` keep `--no-sandbox` and `--yolo`, but their help and reduced-safety banner now say to use them only inside a VM.
- `pikuri-memory`'s mem0 stack has no route out: mem0, Qdrant and the router relay sit on an internal Docker network, a socat `front-door` publishes the API, and `MEM0_TELEMETRY=false` turns off mem0's PostHog telemetry.
- `pikuri-code`'s Bubblewrap sandbox withholds inherited environment variables except the shell's baseline, build-tool options and path-valued ones, a second wall behind keeping secrets out of your environment at all, so a token you missed no longer reaches `bash` or a cloned repo's filters; list extras under `sandbox_env:` in the config file, and add `#env(delta)` and `#withheld_env_names` to any sandbox of your own (`D_sandbox_env_wall`).
- `bin/pikuri-openlibrary` runs `mcp-open-library:1.2.6` with podman when installed (docker otherwise) and with `--cap-drop=all --security-opt=no-new-privileges --read-only`; rebuild the image from a v1.2.6 checkout with the new `pikuri-mcp/containers/mcp-open-library.Containerfile`.
- New `pikuri-mcp/containers/mcp-egress-proxy.Containerfile`, a tinyproxy image that lets an MCP server on an internal network reach only the hosts baked in at build time; `bin/pikuri-code`'s commented MCP examples now run every server in a container (GitHub behind that proxy, a baked npm image, Playwright with Chromium's sandbox on) instead of bare `npx`.
- `pikuri-lsp` no longer answers the first call against a cold ruby-lsp from an index not yet built: the readiness gate's quiet window now starts when `initialized` is sent, not when the server is spawned.
- `pikuri-lsp/bin/pikuri-lsp-check` reports a probe that got nothing to measure (an empty definition, index or hierarchy) as *no answer* instead of *ok*.
- `bin/pikuri-code` counts a project's skills and commands as untrusted, without asking, when a bundle file matches no commit (untracked, ignored or changed since `HEAD`) or the project is not a git repository, via the new `Pikuri::Bundle::Unreviewed`; commit the bundles you reviewed to be asked again.
- `bin/pikuri-code` gains a `/clear` built-in that starts a new conversation.
- `Pikuri::Tasks::ListChanged#to_s` renders one line (`tasks: 1/3 done, now: …`), so a terminal no longer prints the raw event.
- A batch `task_create` emits one `Pikuri::Tasks::ListChanged` instead of one per item, via the new `Pikuri::Tasks::List#add_all`; a listener that counted per-item events sees one per call.
- `task_in_progress` returns any other in-progress task to `pending`, so the list holds at most one in-progress task instead of asking the model to keep it so.
- `pikuri-code`'s Bubblewrap sandbox runs behind `pasta` when installed (package `passt`), so sandboxed `bash` keeps the internet and the LAN but no longer reaches this machine's `127.0.0.1` services; name a host dev server's port under `sandbox_ports:` in the config file, and add `#host_loopback_ports` to any sandbox of your own (`D_sandbox_own_loopback`).
- `bin/pikuri-code`, `bin/pikuri-os` and `bin/pikuri-computer` check `systemd-detect-virt --vm` when a cage is lifted, and say in red when `--yolo`, `--no-sandbox` or `--no-confirm` runs outside a VM, via the new `Pikuri::Code::VirtualMachine`.
- `bin/pikuri-openlibrary` prints what the prompt-injection verifier flagged and exits, instead of crashing with a backtrace.
- `Mem0Server` drops `container_router_url:` and `qdrant_port:` (and `bin/pikuri-memory` its `--mem0-router-url`): an internal network can route nowhere but the relay, and Qdrant is no longer published on the host.
