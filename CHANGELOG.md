# Changelog

All notable changes to the workshop gems. pikuri's own changes are in
[its changelog](https://codeberg.org/mvysny/pikuri/src/branch/master/CHANGELOG.md).

## [Unreleased]

- **Breaking:** `Pikuri::Mcp::Extension.new(registry:, synthesize_descriptions:, verify_mcp_servers:)` is now `Pikuri::Mcp::Extension.new(catalog:)`, one per agent: build the catalog once per process with `Pikuri::Mcp::Catalog.build(registry, transport:, cancellable:, around_request:)` and hand it to every agent (`D_mcp_catalog_and_connections`).
- **Breaking:** `Pikuri::Mcp::Servers` is gone, split into `Pikuri::Mcp::Catalog` (verified once, shared, holds no process) and `Pikuri::Mcp::Connections` (one agent's own servers, started on its first tool call); `Pikuri::Mcp::Servers::Connect` is now `Pikuri::Mcp::Connect`.
- An MCP server process now serves one agent only and starts on that agent's first call to its tools, so a browser logged in during one conversation is never logged in for another, and building an agent spawns nothing.
- **Breaking:** an extension instance added to a second agent now raises `ArgumentError` (pikuri's `Configurator#add_extension`), so a host that reused one `Tasks`, `Skill`, `Memory`, `Lsp` or `Mcp` extension across agents, quietly sharing its task list, skill gate, capture queue or servers, must build one per agent; every agent starts its own language servers (`D_lsp_per_agent`).
- A resumed conversation (`Agent.new(history:)`) gets back the tools of every MCP server it connected, without calling `mcp_connect` again.
- A spawned MCP server that lists different tools than the ones verified at boot is refused with `Pikuri::Mcp::ClientWrapper::SurfaceChanged`, including after a crash restart.
- The MCP verifier's and synthesizer's one-shot agents take the host's `around_request:`, so a request throttle covers them too.
- New `pikuri-conversations`: `Pikuri::Conversations::HistoryFile` stores a conversation in the format pikuri's dropped `History#save` / `.load` wrote, and `Pikuri::Conversations::Store` keeps one folder per conversation as pikuri-webui and Puri did (`D_history_file`).
- `Pikuri::Conversations::Store#history` answers nil for a conversation never saved, so a host passes it straight to `Conversations#open(history:)` without checking for `history.json` first.
- `Pikuri::Conversations::Conversation#close` closes a booting conversation no message waits on, answering `:closing`, so a host deleting it no longer needs `force: true`.
- `Pikuri::Conversations::Conversation#boot` is public, so a host whose listener reads the conversation back opens it with `boot: false` and boots it once it holds it.
- `Pikuri::Conversations` runs many conversations at once, each a `Conversation` with its own agent and turn threads: `submit` starts a turn or injects into the running one, and `cancel`, `switch_model`, `clear`, `close` and `shutdown` are safe from any thread.
- `Pikuri::Conversations::Throttle` bounds the LLM requests in flight per server, process-wide, sized by `Throttle.limit` or from llama.cpp's `/props` slot count, which a conversation probes once per server and model; it replaces the `ServerPermits` pikuri dropped.
- `Pikuri::Conversations::Probe` asks llama.cpp's `/props` for a model's context window, slot count and inputs, in place of the `ContextWindowDetector` pikuri dropped, and hands the agent what it learns; `Pikuri::Conversations::Event::ContextCap` announces the window to the conversation's listener, in place of pikuri's `Agent::Event::ContextCap`.
- `Pikuri::Conversations::Titler` names a conversation from its opening message, the prompt pikuri-webui and Puri used; a conversation opened `untitled: true` asks it once its first turn has ended and reports `Event::Titled`.
- `Pikuri::Conversations::RateLimitedListener` coalesces streamed deltas to an fps cap, in place of the `Listener::RateLimited` pikuri dropped: it flushes ahead of a turn's end, even a failed one, and passes the conversation's own events (`Pikuri::Conversations::Event::ALL`) straight through, so it needs no lock.
- **Breaking:** `Pikuri::Code::Bash.run` and `Pikuri::Code::ExitPlanMode.run` take a required `cancellable:`, which the `bash` and `exit_plan_mode` tools pass from the turn, so a cancel reaches their confirmation while it still waits on the human.
- The workshop requires pikuri `863c1ad`, where `Confirmer#ask` takes the turn's `cancellable:`, and before it `0e5882f`, where an `Agent` never probes the server and announces no context window, and before it `3aed7e2`, where an `Agent` is one conversation, owns its `Interloper`, takes `around_request:` in place of `ServerPermits`, refuses a reused extension instance, and gives an extension one setup hook, so every workshop extension's `bind` moved into `configure`.
- **Breaking:** `Pikuri::Mcp::Connect.new` takes `configurator:` in place of `ctx:`, `Pikuri::Mcp::Connections#register_tools` takes the agent's `Pikuri::Agent::Configurator`, and `Pikuri::Memory::Extension#on_user_message` / `Pikuri::Code::Extension#on_user_message` take no `ctx`.
- **Breaking:** `Pikuri::Skill::Extension#on_conversation_reset`, `Pikuri::Skill::Activation#reset` and `Pikuri::Skill::Activation::Open` are gone: a new conversation is a new agent with a new extension, and every agent has an interloper to carry a promotion.
- **Breaking:** `Pikuri::Tasks::Extension#on_conversation_reset` and `Pikuri::Tasks::List#clear` are gone, since a new conversation's agent gets a new extension and an empty list.
- `bin/pikuri-code`'s `/clear` closes the agent and builds a new one, so MCP and language servers restart and nothing a conversation touched crosses into the next.
- `pikuri-memory`'s Qdrant image is `docker.io/qdrant/qdrant:v1.12.4`, fully qualified like pikuri-vectordb's, so podman finds it without a registry prompt.
- `pikuri-code`, `pikuri-os`, `pikuri-lsp`, `pikuri-mcp`, `pikuri-skills`, `pikuri-tasks`, `pikuri-memory` and `pikuri-extractors` moved here from pikuri; a host that wires one now takes it from this repo, beside pikuri's own gems (`D_separate_repo`).
- The workshop gems carry their own version (`Pikuri::Workshop::VERSION`) and pin pikuri's gems with `~>` instead of pikuri-core's exact version.
- `pikuri-extractors` tags its converter image with a digest of its build context instead of pikuri-core's version, so an unchanged image is never rebuilt.
- `bin/pikuri-code` asks "did you write the files under this directory?" only when the project ships a skill or a slash command, and its `--yolo` help and reduced-safety banner now point at a VM rather than a container.
- `bin/pikuri-os` and `bin/pikuri-computer` keep `--no-sandbox` and `--yolo`, but their help and reduced-safety banner now say to use them only inside a VM.
- `pikuri-memory`'s mem0 stack has no route out: mem0, Qdrant and the router relay sit on an internal Docker network, a socat `front-door` publishes the API, and `MEM0_TELEMETRY=false` turns off mem0's PostHog telemetry.
- `pikuri-code`'s Bubblewrap sandbox withholds inherited environment variables except the shell's baseline, build-tool options and path-valued ones, a second wall behind keeping secrets out of your environment at all, so a token you missed no longer reaches `bash` or a cloned repo's filters; list extras under `sandbox_env:` in the config file, and add `#env(delta)` and `#withheld_env_names` to any sandbox of your own (`D_sandbox_env_wall`).
- `bin/pikuri-openlibrary` runs `mcp-open-library:1.2.6` with podman when installed (docker otherwise) and with `--cap-drop=all --security-opt=no-new-privileges --read-only`; rebuild the image from a v1.2.6 checkout with the new `pikuri-mcp/containers/mcp-open-library.Containerfile`.
- New `pikuri-mcp/containers/mcp-egress-proxy.Containerfile`, a tinyproxy image that lets an MCP server on an internal network reach only the hosts baked in at build time; `bin/pikuri-code`'s commented MCP examples now run every server in a container (GitHub behind that proxy, a baked npm image, Playwright with Chromium's sandbox on) instead of bare `npx`.
- `pikuri-lsp` no longer answers the first call against a cold ruby-lsp from an index not yet built: the readiness gate's quiet window now starts when `initialized` is sent, not when the server is spawned.
- `pikuri-lsp/bin/pikuri-lsp-check` reports a probe that got nothing to measure (an empty definition, index or hierarchy) as *no answer* instead of *ok*.
- `bin/pikuri-code` counts a project's skills and commands as untrusted, without asking, when a bundle file matches no commit (untracked, ignored or changed since `HEAD`) or the project is not a git repository, via the new `Pikuri::Bundle::Unreviewed`; commit the bundles you reviewed to be asked again.
- `bin/pikuri-code` gains a `/clear` built-in that starts a new conversation.
- `Pikuri::Tasks::ListChanged#to_s` renders one line (`tasks: 1/3 done, now: …`), so a terminal no longer prints the raw event.
- A batch `task_create` emits one `Pikuri::Tasks::ListChanged` instead of one per item, via the new `Pikuri::Tasks::List#add_all`; a listener that counted per-item events sees one per call.
- `task_in_progress` returns any other in-progress task to `pending`, so the list holds at most one in-progress task instead of asking the model to keep it so.
- `pikuri-code`'s Bubblewrap sandbox runs behind `pasta` when installed (package `passt`), so sandboxed `bash` keeps the internet and the LAN but no longer reaches this machine's `127.0.0.1` services; name a host dev server's port under `sandbox_ports:` in the config file, and add `#host_loopback_ports` to any sandbox of your own (`D_sandbox_own_loopback`).
- `bin/pikuri-code`, `bin/pikuri-os` and `bin/pikuri-computer` check `systemd-detect-virt --vm` when a cage is lifted, and say in red when `--yolo`, `--no-sandbox` or `--no-confirm` runs outside a VM, via the new `Pikuri::Code::VirtualMachine`.
- `bin/pikuri-openlibrary` prints what the prompt-injection verifier flagged and exits, instead of crashing with a backtrace.
- `Mem0Server` drops `container_router_url:` and `qdrant_port:` (and `bin/pikuri-memory` its `--mem0-router-url`): an internal network can route nowhere but the relay, and Qdrant is no longer published on the host.
